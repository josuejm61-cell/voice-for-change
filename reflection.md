# Project 02 Reflection

## Decisions

One of the biggest decisions I made with Voice for Change was to focus more
on local organizations instead of trying to cover every possible issue.
Originally, I knew I wanted the website to be about helping people make a
difference, but that idea was pretty broad. As I worked on the project, I
realized that highlighting organizations and giving people ways to learn more
about them made the website have a clearer purpose.

I also decided to create individual pages for the organizations instead of
having the gallery images only link to outside websites. I liked this better
because visitors can stay on Voice for Change, learn about the organization,
and then decide if they want to visit its official website.

Another important decision was adding an English and Spanish option. I thought
this was more meaningful than adding another visual effect because it actually
changes how people can use the website.

## What worked

I think that the interactive features are one of the things that worked best. The
gallery can be filtered, the color scheme can be changed, and visitors can
switch between English and Spanish. These features helped make the website
feel more complete compared to my first version.

GitHub Pages also worked really well for this project. I liked being able to
make a change in Visual Studio Code, commit it, push it to GitHub, and then
see that change appear on the live website.

I am also happy with how the organization gallery developed. At first it was
mainly there to display pictures, but now the images can take visitors to
individual pages with more information. That made the gallery actually useful
instead of just being decoration.

## What I Would Do Differently

If I started the project again, I would organize everything better from the
beginning. Some of my image filenames have long names and spaces because they
came directly from screenshots. I would rename them to simple names like
food-bank.png or habitat.png before putting them into the project.

I would also create a consistent page layout earlier. As I added more pages,
I had to copy the header, navigation, buttons, and scripts several times.
Planning that structure earlier would have saved time.

Another thing I would do differently is test on mobile earlier. Most of my
original work was done while looking at the website on my computer. Testing
different screen sizes earlier would have made it easier to catch layout
problems before adding more features.

## What I Learned

What I have learned is that building a website involves a lot more than getting
the first page to work. A small change can affect other parts of the website,
so testing becomes more important as the project gets larger.

I also learned more about how HTML, CSS, and JavaScript work together. HTML
creates the structure, CSS controls how everything looks, and JavaScript can
change how the website responds to the visitor. The language toggle was a good
example because I needed all three parts to make it work correctly.

I also became more comfortable using GitHub. Earlier, committing and pushing
changes felt like an extra step, but now it makes more sense because I can keep
track of changes and update the live website without uploading everything
again.

The biggest thing I learned from this project is that it is better to build
something simple that works well than add a bunch of features that are
unfinished. Voice for Change changed a lot from the first version, but the
changes made the original idea more useful instead of changing the purpose of
the project.
